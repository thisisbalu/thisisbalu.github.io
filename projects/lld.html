02Design Patterns
Behavioral
Strategy
One interface, four implementations. Registry stores and calls strategies without knowing which algorithm runs — pure delegation.
interface RateLimiterStrategy {
    RateLimitResult tryAcquire();
}
// TokenBucket, SlidingWindowLog,
// FixedWindowCounter, LeakyBucket
Adding an algorithm = one new class + one factory case. Service and Registry are untouched.
Creational
Factory
The only place algorithm names appear as strings. Unknown names throw immediately — fail fast at startup, not at request time.
switch (config.algorithm) {
  case "TokenBucket":
    return new TokenBucket(...);
  case "SlidingWindowLog":
    return new SlidingWindowLog(...);
  default: throw new IllegalArgumentException();
}
Structural
Registry
Two-level map: endpoint → clientId → strategy. Lazy-created on first request per pair.
// Map<endpoint, Map<clientId, Strategy>>
store
  .computeIfAbsent(endpoint,
    e -> new HashMap<>())
  .computeIfAbsent(clientId,
    c -> factory.create(config));
Threaded: both Maps become ConcurrentHashMap. computeIfAbsent stays atomic per key.

02Design Patterns
Behavioral
Command
Request is the command object — it encapsulates source, destination, direction, type, and timestamp. Button creates it; Controller consumes it.
class Button {
  public void press(int destFloor) {
    Request r = new Request(floor, direction);
    controller.addRequest(r);
  }
}
// Controller: requestQueue.take()
Request is immutable after construction — safe to pass between threads without locking.
Behavioral
State
ElevatorCar tracks ElevatorState and Direction. Door tracks DoorState. State drives valid transitions and the score() for dispatch.
enum ElevatorState {
    IDLE, MOVING_UP, MOVING_DOWN,
    DOOR_OPEN, MAINTENANCE
}
// score() returns MAX_VALUE when
// state == MAINTENANCE
volatile on state and direction fields — visible to the dispatcher thread without locking.
Concurrency
Producer-Consumer
Buttons (producers) put Requests into a LinkedBlockingQueue. Dispatcher thread (consumer) calls take() — blocks when idle, no busy-waiting.
class ElevatorController {
  BlockingQueue<Request> requestQueue
    = new LinkedBlockingQueue<>();

  // producer: requestQueue.offer(r)
  // consumer: requestQueue.take()
}
Decouples button press timing from dispatch processing. No shared lock between producers and consumer.

02Design Patterns
Behavioral
Strategy
PricingStrategy interface lets Gate calculate fees without knowing the algorithm. Swap HourlyPricing for DailyPricing or ValidationPricing without touching Gate.
interface PricingStrategy {
    double calculate(Ticket ticket);
}
class HourlyPricing implements PricingStrategy {
    public double calculate(Ticket t) {
        long hours = (t.getDurationMinutes()+59)/60;
        return hours * ratePerHour;
    }
}
Behavioral
State
SpotState drives which operations are valid. assign() transitions AVAILABLE→OCCUPIED. free() reverses it. All state-mutating methods are synchronized.
enum SpotState {
    AVAILABLE, OCCUPIED,
    RESERVED, MAINTENANCE
}
// assign(): AVAILABLE → OCCUPIED
// free():   OCCUPIED  → AVAILABLE
// reserve()/maintenance(): terminal
synchronized on every state method — assign() check-and-set is atomic, preventing double-assignment.
Concurrency
Retry on TOCTOU
findAvailableSpot() and assign() are non-atomic — another thread can grab the spot between them. Gate retries up to MAX_RETRIES if assign() returns false.
for (int attempt = 0;
     attempt < MAX_RETRIES; attempt++) {
  Optional<ParkingSpot> spot =
      lot.findAvailableSpot(type);
  if (spot.get().assign(vehicle))
    return Optional.of(new Ticket(...));
  // false → another thread grabbed it
}
assign() is the authoritative check — synchronized, atomic. Gate is the optimistic caller with retry.

02Design Patterns
Behavioral
State
VendingMachine delegates every action to its current state object. IdleState blocks selection; HasMoneyState checks funds and transitions to Dispensing; OutOfStockState rejects everything silently.
interface VendingMachineState {
    void insertCoin(VendingMachine vm, Coin c);
    void selectProduct(VendingMachine vm, String id);
    void dispense(VendingMachine vm);
    void cancel(VendingMachine vm);
}
// IdleState, HasMoneyState,
// DispensingState, OutOfStockState
State objects are stateless — they receive the machine as a parameter and mutate its data, so all 4 can be shared singletons.
Behavioral
Observer
InventoryObserver fires after every stock change. Inventory calls onLowStock when quantity hits the threshold and onOutOfStock at zero — no polling, pure push.
interface InventoryObserver {
    void onLowStock(Product p, int remaining);
    void onOutOfStock(Product p);
}
// AdminAlert implements InventoryObserver
// Triggered inside Inventory.decrement()
Observer list lives in Inventory — the state machine never imports or knows about AdminAlert.
Concurrency
Lock-per-session
A single ReentrantLock on VendingMachine serializes entire customer sessions. insertCoin, selectProduct, and cancel each acquire/release the lock, preventing interleaving from concurrent users.
class VendingMachine {
  private final ReentrantLock lock
      = new ReentrantLock();

  public void insertCoin(Coin coin) {
      lock.lock();
      try { state.insertCoin(this, coin); }
      finally { lock.unlock(); }
  }
}
dispense() is called internally while the lock is already held — no re-lock needed. Product.decrementIfAvailable() uses a CAS loop for the inventory side.

02Design Patterns
Behavioral
Strategy
SearchStrategy decouples the search algorithm from Library. Swap SearchByTitle for SearchByAuthor or SearchByISBN at the call site — Library.search() never changes.
interface SearchStrategy {
    List<Book> search(Catalog c, String query);
}
// SearchByTitle, SearchByAuthor,
// SearchByISBN
// library.search(new SearchByAuthor(), q)
New search dimension = one new class. Catalog exposes getAllBooks() and getBook() so strategies can iterate without knowing internals.
Behavioral
Observer
LibraryObserver receives push notifications for overdue books and low-copy warnings. Library fires on borrowBook() and checkOverdue() — observers are never polled.
interface LibraryObserver {
    void onOverdue(BorrowRecord record);
    void onLowCopies(Book book, int remaining);
}
// EmailNotifier implements LibraryObserver
// Library fires after borrowBook/checkOverdue
In the threaded version, the observer list is CopyOnWriteArrayList — safe iteration while new observers can register concurrently.
Concurrency
ReadWriteLock
Catalog reads (search, findAvailableItem) are frequent; writes (addBook, addBookItem) are rare. ReadWriteLock allows unlimited concurrent readers and serializes writers without blocking readers.
class Catalog {
  private final ReadWriteLock rwLock
      = new ReentrantReadWriteLock();

  // search/find → rwLock.readLock()
  // addBook/addItem → writeLock()
}
BookItem.checkout() and checkin() are synchronized independently — the catalog lock protects the map structure, not the individual item state.
